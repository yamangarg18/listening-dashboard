## NOTION API REFERENCE — CREATE A PAGE

### Endpoint

```
POST https://api.notion.com/v1/pages
```

### Headers (same for all Notion API calls)

```python
headers = {
    "Authorization": f"Bearer {NOTION_API_KEY}",
    "Content-Type": "application/json",
    "Notion-Version": "2022-06-28",
}
```

### Request Body

```json
{
  "parent": {
    "database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  },
  "properties": {
    "Property Name": {
      ...property value object...
    }
  }
}
```

**CRITICAL RULES:**
- The `parent.database_id` must be the ID of an existing database that the integration has access to.
- The keys in `properties` must **exactly match** the property names in the database (case-sensitive).
- You only need to include properties you want to set. Omitted properties get their default values (empty/unchecked/null).
- The `title` property is required — every page must have a title.
- Properties that are auto-generated by Notion (`created_time`, `created_by`, `last_edited_time`, `last_edited_by`) must NOT be included in the request. Notion creates these automatically. Including them returns a `400 validation_error`.

### Response (200 OK)

```json
{
  "object": "page",
  "id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "created_time": "2026-04-03T10:00:00.000Z",
  "last_edited_time": "2026-04-03T10:00:00.000Z",
  "archived": false,
  "url": "https://www.notion.so/Page-Title-xxxxxxxx...",
  "parent": {
    "type": "database_id",
    "database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  },
  "properties": {
    "Title": {
      "id": "title",
      "type": "title",
      "title": [
        {
          "type": "text",
          "text": { "content": "Page Title" },
          "plain_text": "Page Title"
        }
      ]
    }
  }
}
```

The `id` field in the response is the **page ID** — save this when you need to reference the page later (for relations, updates, etc.).

### Error Responses

| Status | Code | Meaning | Action |
|--------|------|---------|--------|
| 400 | `validation_error` | Property name doesn't exist in database, wrong value format, or tried to set auto-generated property | Fix the property name or value format. Log the full error message — Notion usually tells you exactly which property is wrong. |
| 401 | `unauthorized` | Bad API key | Check NOTION_API_KEY |
| 404 | `object_not_found` | Database ID doesn't exist or not shared with integration | Check database_ids.json |
| 409 | `conflict_error` | Transaction conflict (rare, retry-safe) | Retry the request |
| 429 | `rate_limited` | Too many requests (3/sec limit) | Wait for `Retry-After` seconds, then retry |

## PROPERTY VALUE FORMATS — WRITING

When creating a page, each property value has a specific JSON format. These are DIFFERENT from the formats used when creating a database (Chunk 1 defined property schemas; this chunk defines property values).

### Title (required — every page must have one)

```python
"Title": {
    "title": [
        {
            "type": "text",
            "text": {"content": "Your page title here"}
        }
    ]
}
```

The title value is an array of rich text objects. For a simple string, it's always a single-element array with `type: "text"`.

**Empty title:**
```python
"Title": {
    "title": [
        {
            "type": "text",
            "text": {"content": ""}
        }
    ]
}
```

### Rich Text

```python
"One-Line Summary": {
    "rich_text": [
        {
            "type": "text",
            "text": {"content": "Your text content here"}
        }
    ]
}
```

Same array-of-objects format as title. For a simple string, single-element array.

**Empty rich text:**
```python
"One-Line Summary": {
    "rich_text": []
}
```

**Rich text has a 2000 character limit per text object.** If your content is longer than 2000 characters, split it into multiple text objects in the array:

```python
"Full Content": {
    "rich_text": [
        {
            "type": "text",
            "text": {"content": "first 2000 chars..."}
        },
        {
            "type": "text",
            "text": {"content": "next 2000 chars..."}
        }
    ]
}
```

### URL

```python
"URL": {
    "url": "https://example.com/article"
}
```

**Null/empty URL:**
```python
"URL": {
    "url": null
}
```

The value is a plain string, not an array. Must be a valid URL starting with `http://` or `https://`.

### Number

```python
"Confidence Score": {
    "number": 0.85
}
```

**Null number:**
```python
"Confidence Score": {
    "number": null
}
```

The value is a plain number (integer or float), not a string.

### Select

```python
"Signal Level": {
    "select": {"name": "High"}
}
```

**Null/empty select:**
```python
"Signal Level": {
    "select": null
}
```

The value is an object with a `name` key. The name must match one of the options defined in the database schema. If you pass a name that doesn't exist as an option, Notion returns a `400 validation_error`.

### Multi-Select

```python
"Topic Tags": {
    "multi_select": [
        {"name": "Robotics"},
        {"name": "India"},
        {"name": "Policy"}
    ]
}
```

**Empty multi-select:**
```python
"Topic Tags": {
    "multi_select": []
}
```

The value is an array of objects, each with a `name` key. Unlike select, **multi-select auto-creates new options** — if you pass a name that doesn't exist in the database schema, Notion creates it automatically. This is intentional for Key Entities and Topic Tags, which are populated dynamically.

### Date

```python
"Published Date": {
    "date": {"start": "2026-04-03"}
}
```

**Date with time and timezone:**
```python
"Discovered Date": {
    "date": {"start": "2026-04-03T14:30:00.000+05:30"}
}
```

**Null/empty date:**
```python
"Published Date": {
    "date": null
}
```

The `start` value is an ISO 8601 string. Date-only (`"2026-04-03"`) or datetime with timezone (`"2026-04-03T14:30:00.000+05:30"`). If no timezone is provided in a datetime, Notion defaults to UTC.

### Checkbox

```python
"Seen By User": {
    "checkbox": false
}
```

The value is a plain boolean — `true` or `false`. Not a string, not wrapped in an object.

### Relation

```python
"Linked Entries": {
    "relation": [
        {"id": "page-id-1-xxxx-xxxx"},
        {"id": "page-id-2-xxxx-xxxx"}
    ]
}
```

**Empty relation:**
```python
"Linked Entries": {
    "relation": []
}
```

The value is an array of objects, each with an `id` key containing a **page ID** (not a database ID). This links the current page to other pages in the related database.

#### `_get_client() -> httpx.Client`

Private function that returns a configured httpx client. Reused by all functions in the module.

```python
import httpx
from config import NOTION_API_KEY, NOTION_API_VERSION, NOTION_BASE_URL

def _get_client() -> httpx.Client:
    """Return a configured httpx client for Notion API calls."""
    return httpx.Client(
        base_url=NOTION_BASE_URL,
        headers={
            "Authorization": f"Bearer {NOTION_API_KEY}",
            "Content-Type": "application/json",
            "Notion-Version": NOTION_API_VERSION,
        },
        timeout=30.0,
    )
```

#### `_handle_response(response: httpx.Response) -> dict`

Private function that checks the response status and raises a descriptive exception on error.

```python
def _handle_response(response: httpx.Response) -> dict:
    """
    Check response status. Return JSON body on success.
    Raise exception with details on failure.
    """
    if response.status_code == 200:
        return response.json()

    error_body = response.json()
    error_code = error_body.get("code", "unknown")
    error_message = error_body.get("message", "No message")

    raise Exception(
        f"Notion API error {response.status_code}: "
        f"[{error_code}] {error_message}"
    )
```

#### `_format_rich_text(text: str) -> list`

Helper that converts a plain string into Notion's rich text array format, handling the 2000 character limit.

```python
def _format_rich_text(text: str) -> list:
    """
    Convert a plain string to Notion rich text array format.
    Splits into chunks of 2000 characters if needed.
    
    Args:
        text: Plain string to format
        
    Returns:
        List of rich text objects ready for Notion API
    """
    if not text:
        return []
    
    chunks = []
    for i in range(0, len(text), 2000):
        chunks.append({
            "type": "text",
            "text": {"content": text[i:i+2000]}
        })
    return chunks
```

#### `create_page(database_id: str, properties: dict) -> str`

The main function. Creates a page in a Notion database.

```python
def create_page(database_id: str, properties: dict) -> str:
    """
    Create a new page in a Notion database.
    
    Args:
        database_id: UUID of the target database
        properties: Dict of property names to property value objects.
                    Values must be in Notion API format (see property 
                    value formats in CHUNK_02 spec).
    
    Returns:
        The page ID (UUID string) of the created page.
    
    Raises:
        Exception: If the Notion API returns an error.
    """
```

Implementation requirements:
- Build the request payload with `parent.database_id` and `properties`
- Send `POST /v1/pages`
- Use `_handle_response()` to check for errors
- Log the page title and page ID on success
- Return the page ID
- Use `tenacity` retry decorator for 429 and 5xx errors:

```python

@retry(

    retry=retry_if_exception(lambda e: "429" in str(e) or "5" in str(e)[:1]),
    reraise=True,
)
def create_page(database_id: str, properties: dict) -> str:
    ...
```

#### `build_page_properties(**kwargs) -> dict`

Helper that builds a Notion-formatted properties dict from simple Python values. This makes it easy for other modules to create pages without knowing Notion's JSON format.

```python
def build_page_properties(
    title: str,
    url: str | None = None,
    rich_text_fields: dict[str, str] | None = None,
    select_fields: dict[str, str] | None = None,
    multi_select_fields: dict[str, list[str]] | None = None,
    date_fields: dict[str, str] | None = None,
    number_fields: dict[str, float | int] | None = None,
    checkbox_fields: dict[str, bool] | None = None,
    relation_fields: dict[str, list[str]] | None = None,
    title_property_name: str = "Title",
) -> dict:
    """
    Build a Notion-formatted properties dict from simple Python values.
    
    Args:
        title: The page title (required)
        url: URL value for the "URL" property
        rich_text_fields: {"Property Name": "text content", ...}
        select_fields: {"Property Name": "Option Name", ...}
        multi_select_fields: {"Property Name": ["Tag1", "Tag2"], ...}
        date_fields: {"Property Name": "2026-04-03", ...}  (ISO 8601)
        number_fields: {"Property Name": 0.85, ...}
        checkbox_fields: {"Property Name": True, ...}
        relation_fields: {"Property Name": ["page-id-1", "page-id-2"], ...}
        title_property_name: Name of the title property (default "Title",
                            but some databases use different names like 
                            "Entry Title" or "Brief Title")
    
    Returns:
        Dict ready to pass to create_page() as the properties argument.
    
    Example:
        props = build_page_properties(
            title="New research paper on robotics",
            url="https://arxiv.org/abs/2026.12345",
            rich_text_fields={
                "One-Line Summary": "A new approach to...",
                "Why It Matters": "This could impact...",
            },
            select_fields={
                "Signal Level": "High",
                "Category": "Research",
            },
            multi_select_fields={
                "Topic Tags": ["Robotics", "AI"],
                "Key Entities": ["Boston Dynamics", "MIT"],
            },
            date_fields={
                "Published Date": "2026-04-03",
                "Discovered Date": "2026-04-03T14:30:00+05:30",
            },
            number_fields={"Confidence Score": 0.92},
            checkbox_fields={"Seen By User": False},
        )
        page_id = create_page(database_id, props)
    """
```

Implementation requirements:
- Always include the title property using `title_property_name` as the key
- For each `rich_text_fields` entry, use `_format_rich_text()` to convert
- For each `select_fields` entry, wrap as `{"select": {"name": value}}`
- For each `multi_select_fields` entry, wrap as `{"multi_select": [{"name": v} for v in values]}`
- For each `date_fields` entry, wrap as `{"date": {"start": value}}`
- For each `number_fields` entry, wrap as `{"number": value}`
- For each `checkbox_fields` entry, wrap as `{"checkbox": value}`
- For each `relation_fields` entry, wrap as `{"relation": [{"id": v} for v in values]}`
- If `url` is provided, add `{"url": url}`
- Skip any field group that is None
- Return the assembled dict

## EDGE CASES

### Property name mismatch
If you pass a property name that doesn't exist in the database (e.g., "signal_level" instead of "Signal Level"), Notion returns:
```json
{
  "code": "validation_error",
  "message": "Signal_level is not a property that exists."
}
```
The error message tells you exactly which property is wrong. Log it.

### Select option doesn't exist
If you pass a select value that isn't in the database's options list:
```json
{
  "code": "validation_error", 
  "message": "... is not a valid option for ..."
}
```
Multi-select does NOT have this problem — it auto-creates new options.

### Rich text over 2000 characters
Notion's API rejects any single text object with content over 2000 characters. The `_format_rich_text()` function must split long strings into 2000-char chunks. If the total content across all chunks exceeds Notion's overall limit (currently ~100,000 characters per property), the API returns a 400 error. This is unlikely in normal operation but could happen with the "Full Content" field from Extract API.

### Empty properties
Omitting a property from the `properties` dict is fine — Notion uses the default (empty string, unchecked, null). You do NOT need to explicitly set empty values unless you want to overwrite existing data (relevant in Chunk 4 — Update).

### Rate limiting during batch writes
When creating many pages quickly (e.g., writing 30 search results to Ingestion Queue), you'll hit the 3 req/sec limit. The `tenacity` retry decorator handles 429 errors with exponential backoff. Additionally, add a `time.sleep(0.35)` between calls in any loop that writes multiple pages. This is done by the calling code (e.g., `ingestion.py` in Chunk 9), not inside `create_page()` itself.

### URL validation
Notion accepts any string as a URL value — it doesn't validate the format. But passing a string that's clearly not a URL (e.g., "not a url") will show as broken in the Notion UI. The calling code should validate URLs before passing them, but `create_page()` itself should not — it's a generic function.

### Relation to non-existent page
If you pass a page ID in a relation field that doesn't exist, Notion returns a `400 validation_error`. The calling code must ensure page IDs are valid before creating relations.
